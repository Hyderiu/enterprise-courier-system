# 公开版隐私处理说明

## 已排除内容

- 生产 `.env`、会话密钥、发布配置和远端连接信息。
- 生产数据库及 WAL/SHM 文件、备份、日志、账单上传文件和导出文件。
- 承运商密钥、客户编码、月结号、店铺 ID 和回调令牌。
- CRM/钉钉 AppId、Secret、Token、内部 URL 与企业域名。
- 真实员工、手机号、地址、部门、项目、订单、运单、审批和费用数据。
- 绑定本机真实员工身份的本地生产入口。

## 演示数据方法

公开版没有复制生产数据库后进行简单遮罩，而是由脚本重新生成独立数据。这能避免姓名虽被替换但地址、项目、时间、运单等组合仍可重识别个人的问题。

保留的是业务结构：

- 三个地区和三家承运商的组合。
- 待审核、待揽收、已揽收、在途、派送、签收、拒收、取消等状态形态。
- 部门费用与项目费用两种归属。
- 项目到执行部门的关联。
- 报价、实际费用、审批与物流时间等字段关系。

全部演示标识使用 `demo`/`DEMO` 前缀或明显虚构内容。

## 发布前复检

每次准备推送前至少检查：

```powershell
git status --short
git ls-files
git grep -n -I -E "(SECRET|TOKEN|PASSWORD|PRIVATE.KEY)"
git grep -n -I -E "([0-9]{11}|BEGIN.*PRIVATE KEY)"
```

命中不一定是泄露（例如空配置名或虚构号码），但每一项都应人工确认。建议同时启用 GitHub Secret Scanning 和 Push Protection。

## 如果密钥误提交

删除文件或修改 Git 历史并不能使已公开的密钥恢复安全。必须先在对应平台撤销/轮换密钥，再清理仓库历史并重新扫描。
